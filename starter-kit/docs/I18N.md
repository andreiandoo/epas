# Multi-locale (i18n)

A site can serve several languages. UI strings, kind nouns, and API content all
switch with the active locale; SEO gets `hreflang` alternates.

## Enable it
In `site.config.php`:
```php
'locale'  => 'ro',                 // default/base locale
'locales' => ['ro', 'en', 'hu'],   // enabled locales (≤1 → i18n off, no switcher)
```
That's all. The header shows a language switcher; `?lang=xx` switches and is
remembered in a cookie. Resolution order: `?lang=` → cookie → `Accept-Language`
→ default.

## The three translation surfaces
1. **UI strings** — `t('cart.title')` reads `kit/lang/<locale>.php`.
   - Base dictionary = `kit/lang/<default-locale>.php` (fallback for every key).
   - A missing key renders as the key itself (visible in dev).
   - Interpolation: `t('newsletter.subtitle', ['events' => kit_term('events')])`.
   - Per-site overrides: `site.config.php` → `'lang' => ['en' => ['cart.title' => '…']]`.
2. **Kind nouns** — `kit_term('events_cap')` is locale-aware. The kind manifest
   ships `terms` (default locale) + `terms_i18n => ['en' => [...], 'hu' => [...]]`.
3. **API content** (event titles, descriptions) — for multi-locale sites the kit
   automatically adds `locale=<active>` to API requests (and to the browser proxy
   calls), so the backend returns translated content. The locale is part of the
   cache key, so each language caches separately.

## Adding a language
1. Copy `kit/lang/ro.php` → `kit/lang/<code>.php` and translate the values.
2. Add `terms_i18n['<code>']` to each kind you use (or rely on the default-locale
   terms as fallback).
3. Add `nav.<key>` entries in the new lang file for menu labels (the header
   prefers `nav.<key>`, falling back to the kind's label).
4. Add `<code>` to the site's `locales`.

## Authoring rule
In pages/components, wrap **UI strings** in `t('…')` and **nouns** in
`kit_term('…')`. Never hard-code a user-facing string. For strings used inside an
Alpine `<script>`, inject them via PHP: `L: <?= json_encode(['x'=>t('key')]) ?>`
and reference `L.x` in the JS (see `pagesets/checkout.php`, `login.php`).

## What's translated vs. not
Translated: header/nav, CTA, footer newsletter, cookie consent, cart, checkout,
confirmation, auth, account area, error pages, event/schedule/ticket UI labels,
badges. Marketing body copy in `about`/`epk`/`music` pagesets is placeholder text
you localize per site (or drive from the API). The `hreflang` set is emitted
automatically by `kit_seo_tags`.
